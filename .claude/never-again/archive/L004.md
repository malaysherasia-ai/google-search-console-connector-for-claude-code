# L004: Check granted OAuth scopes before saving tokens

**Symptom:** While testing sign-in for the website (2026-10-19), Google's consent screen showed "View and manage Search Console data for your verified sites" as a checkbox that starts unticked. Clicking Continue without ticking it still "signed in": the Connect page moved on to "Choose a property" and then failed with Google's raw 403, and the earlier, working sign-in had been overwritten.

**Cause:** Google's granular consent lets the user untick individual scopes, and the token response's `scope` then lists only what was granted. `exchangeCode` in `src/oauth.ts` saved whatever came back without comparing it to the scopes the app needs, so a token with no Search Console access replaced a good one.

**Rule:** After an OAuth code exchange, check the granted `scope` contains every scope the feature needs before saving tokens; otherwise explain which box to tick and keep the existing tokens.

**Fix:** `exchangeCode` throws a "tick the box" error and does not save when `SEARCH_CONSOLE_SCOPE` is missing; the Connect sign-in step tells people to tick the box before they leave for Google. The site-verification upgrade already re-checks `VERIFY_SCOPE` with `hasScope` before use.

**What would have gone red:** nothing. Demo mode never runs the OAuth exchange; only a live sign-in with the box unticked shows it.
